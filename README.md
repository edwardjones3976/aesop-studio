# Aesop Studio

A personal, local-first browser workspace for AI projects on Windows. Open a project, choose its provider, attach files, chat or run a supervised agent task, inspect and save the results, then close and resume later.

- **Chat & Model Lab:** project conversations through the official `codex` (ChatGPT plan) and `claude` (claude.ai plan) CLIs. You can preview the exact context before it is sent.
- **Developer workspace / Agent control:** supervised agent tasks scoped to the project folder. Each task shows live redacted output, the files it changed, and a cancel button that stops the owned process tree. Interrupted tasks are reconciled on restart and never replayed automatically.
- **Research & Knowledge:** a cited notebook mixing public pages (fetched SSRF-safely) and approved local documents. Exports can include or exclude private sources.
- **Project memory:** authoritative records, source-linked derived summaries, and explicitly promoted shared knowledge. Corrections supersede old records and keep them for provenance.
- **Evidence:** live views of the budget ledger, acceptance matrix, task outcomes and latency samples, plus backup and a restore test.

No dependencies beyond Python 3.11+ (stdlib only). There is no build step and nothing is installed globally.

## Start / stop (Windows)

```powershell
.\start.ps1          # starts on http://127.0.0.1:8765 and opens the one-time launch link
.\stop.ps1           # stops the server started by start.ps1
```

Data lives in `%LOCALAPPDATA%\AesopStudio` (override with `-Data` or `AESOP_DATA`). The server binds to **127.0.0.1 only**. A browser session needs the one-time launch link written to `launch-link.txt` at startup. Restart to get a new link.

## Providers

| Route | How it is verified | Billing |
|---|---|---|
| `codex` | `codex login status` → "Logged in using ChatGPT" | ChatGPT plan quota, $0 incremental |
| `claude` | `claude auth status` → `authMethod: claude.ai` | Claude plan quota, $0 incremental |
| `openai-api` | `OPENAI_API_KEY` present | Metered, **disabled** until the owner sets operating limits |
| cursor / perplexity / firecrawl | not integrated | Handoff only, not counted as integrations |

Studio never reads credential files. `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` are removed from child-process environments so the CLIs use subscription sign-in. To sign in: `codex login`, `claude auth login`. After that, choose **Providers → Re-verify** in the app.

## Permissions model

- Each project has one selected root folder. Agent tasks run there and nowhere else. Drive roots, your home folder, and credential folders are refused.
- Sending attached files to a provider needs a per-project, per-provider transfer permission (Settings). The chat text itself goes to the project's provider.
- Switching away from a project's default provider requires an explicit confirmation. There is no automatic fallback.
- Only one agent writer runs per project at a time. Archiving a project hides it and never deletes files.

## Tests

```powershell
python -W ignore -m unittest tests.test_studio
```

Offline tests use a `SIMULATED` adapter (enabled only with `AESOP_SIMULATED_ROUTE=1`), which is never counted as a live provider. Live provider results are recorded in `docs/report.html`.

## Backup / restore

Use **Evidence → Create backup**, or call `aesop_studio.backup.create_backup`. This takes a consistent SQLite snapshot plus the stored files, with a SHA-256 manifest. **Test restore** unpacks the latest backup into `restore-tests/<timestamp>` and verifies hashes, `PRAGMA integrity_check`, and row counts. It never restores over live data. Credentials are not included: run `codex login` / `claude auth login` again on a new machine.

## Repair procedure

Tasks that were running when Studio stopped become `INTERRUPTED` or `EFFECT_UNKNOWN`, and a `repairs` row (`OPEN_FOREMAN`) is opened with a reproducer hash. Review the task's changed files, then resubmit manually if needed. Nothing is replayed automatically.

## Docs

- `docs/vision.md`: vision charter and foundation decision record
- `docs/plan.html`: mission planning document
- `docs/report.html`: completion report, generated by `python -m aesop_studio.report`
- `docs/acceptance.json`, `docs/research.json`: the shared evidence model, used by both the dashboard and the report
